Duplicate-target queue, live

This fourth widget is deliberately pointed at Pane 1's own target id. Two <browser-glass> elements on the same target, sharing the same gateway connection, cannot both paint a picture at once (there is exactly one canvas per subscribed stream); this one starts in the duplicate-target error state instead of silently fighting Pane 1 for the same canvas. Disconnect Pane 1 below and this one attaches automatically, using the wire subscription that was kept alive for it the whole time.
